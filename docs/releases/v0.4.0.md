## Known Limitations

- harmonIA remains a connected desktop app and requires a reachable API for successful analysis submission.
- No hosted staging or production API exists yet.
- Offline AI processing, local model packaging, Python/FastAPI sidecar packaging, and automatic model downloads remain out of scope.
- Clean-machine installation has not been executed.
- MSI/NSIS artifacts are unsigned and may trigger Windows SmartScreen, Microsoft Defender, browser download protection, UAC, or enterprise policy warnings.
- Code signing is deferred; no certificate, paid signing service, signing secret, or signed workflow was added.
- Existing diagnostic installer artifacts were generated before this release-prep commit and should not be treated as fresh `v0.4.0` release installers.
- The production CSP/API target allow-list remains a future hardening item.
- Backend uploaded-audio retention and storage policy remain future release-safety work before wider testing.

## Release Notes For Users

harmonIA `v0.4.0` is a connected desktop distribution-readiness checkpoint. It improves API environment configuration, local developer startup, Windows build diagnostics, installer safety documentation, and release provenance before broader testing.

This checkpoint does not publish a production-ready Windows installer. The current installer evidence remains internal-only while clean-machine installation, signing, and broader sharing approval are still pending.

Before creating the `v0.4.0` tag, Linus should:

- confirm user approval for the release checkpoint;
- bump root, desktop, and Tauri version metadata to `0.4.0`;
- update this document from `Awaiting approval` to `Approved`;
- rerun the release validation gates after the metadata bump;
- commit the release metadata update;
- create and push the `v0.4.0` tag.

If the metadata bump triggers a new Windows diagnostic build, any new installer artifacts must be treated as unreviewed until RLS3-001 and RLS3-003 evidence is refreshed for that run.

## Rollback Suggestion Criteria

Suggest rollback to `v0.3.0` if:

- the desktop app cannot load the analysis workspace;
- the desktop app no longer defaults to the local API target without configuration;
- configured API URLs are ignored or malformed;
- valid local audio uploads no longer create queued jobs;
- upload validation accepts unsupported, empty, or oversized files silently;
- `npm audit`, desktop build, desktop tests, backend/worker tests, or Python compile checks fail after release;
- release artifacts are found to include secrets, local user files, raw uploaded audio, development caches, or private machine paths beyond documented build metadata;
- installer artifacts are shared beyond the approved scope.

Rollback must be suggested and approved before execution.
